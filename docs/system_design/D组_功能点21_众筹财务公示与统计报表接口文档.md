# D组 功能点21 接口文档：众筹财务公示与统计报表


| 对应控制器 `CrowdfundingProjectsController`、`DonationsController`、`ExpenseRecordsController`、`FinancialDisclosureController`、`StatisticsReportsController` |
| 对应数据库表 `FUND_CROWDFUNDINGPROJECTS`、`FUND_DONATIONS`、`FUND_FINANCERECORDS`、`RPT_STATISTICSSNAPSHOTS` |


## 1. 公共约定

- 请求体与成功响应体使用 `application/json`；控制器返回的业务错误为文本字符串。
- JSON 字段采用 camelCase；所有 ID 均为最长 36 字符的字符串，创建时由后端生成 UUID。
- 日期时间使用 ISO 8601，例如 `2026-08-03T09:30:00Z`。
- 查询列表无数据时返回 `200` 和空数组 `[]`，不是 `404`。
- `POST` 成功返回 `201`、新对象和 `Location` 响应头；`PUT`、`DELETE` 成功返回 `204`，响应体为空。状态变更类接口（`/status`、`/audit`、`/confirm` 等）成功返回 `200` 与 JSON 消息。
- 业务状态字符串使用大写英文常量（如 `ACTIVE`、`APPROVED`），后端比较时大小写不敏感，写入时统一通过 `ToUpperInvariant` 规范化。
- 涉及事务性写入的接口（捐赠入账、支出审核、统计快照生成）会在并发状态变化时返回 `409 Conflict`，客户端应刷新后重试。
- 金额字段（`targetAmount`、`raisedAmount`、`amount`、`metricValue` 等）使用 `decimal`，单位为人民币元。
- `PUT` 是完整更新。除 ID 可省略外，应提交该资源需要保留的全部字段；请求体中若带 ID，必须与 URL 中的 ID 相同。

## 3. 数据结构

### 3.1 FundCrowdfundingProject（众筹项目）

对应数据库表 `FUND_CROWDFUNDINGPROJECTS`，状态集合由 `ProjectStatuses` 定义：`ACTIVE`（进行中，接受捐赠）、`COMPLETED`（已结束）、`CANCELLED`（已取消）。

| 字段 | 类型 | POST 必填 | PUT 必填 | 说明 |
|---|---|---:|---:|---|
| `projectID` | string | 否 | 否 | POST 时忽略并由后端生成；PUT 时如提供，必须与 URL 的 `id` 相同 |
| `catID` | string/null | 否 | 否 | 关联猫咪 ID；非空时必须存在 |
| `title` | string | 是 | 是 | 项目标题，非空 |
| `targetAmount` | decimal/null | 否 | 否 | 目标金额（元），不能为负 |
| `raisedAmount` | decimal/null | 否 | 否 | 已筹金额（元），POST 时被后端强制置为 0，由系统在事务中随捐赠累加 |
| `startTime` | datetime/null | 否 | 否 | 项目开始时间 |
| `endTime` | datetime/null | 否 | 否 | 项目结束时间，不能早于 `startTime` |
| `projectStatus` | string/null | 否 | 否 | 项目状态，取值见 `ProjectStatuses`；POST 未提供时默认 `ACTIVE` |

### 3.2 FundDonation（捐赠记录）

对应数据库表 `FUND_DONATIONS`。`publicFlag` 默认值为 `0`（匿名），仅在 `publicFlag=1` 时财务公示才展示捐赠人信息。

| 字段 | 类型 | POST 必填 | PUT 必填 | 说明 |
|---|---|---:|---:|---|
| `donationID` | string | 否 | — | 后端生成；本模块不提供 PUT 修改捐赠的接口 |
| `projectID` | string | 是 | — | 所属众筹项目 ID，必须存在且为 `ACTIVE` 状态 |
| `donorUserID` | string/null | 否 | — | 捐赠人 ID；非空时必须存在 |
| `amount` | decimal | 是 | — | 捐赠金额（元），必须为正数 |
| `payMethod` | string/null | 否 | — | 支付方式，如 `WECHAT`、`ALIPAY` |
| `payTime` | datetime/null | 否 | — | 支付时间 |
| `publicFlag` | integer/null | 否 | — | 是否公开：`1`=公开、`0`=匿名；未提供时由后端默认置为 `0` |

### 3.3 FundExpenseRecord（支出记录）

对应数据库表 `FUND_FINANCERECORDS`（仅记录支出，收入由 `FUND_DONATIONS` 跟踪）。审核状态集合由 `AuditStatuses` 定义：`PENDING`（待审核）、`APPROVED`（已通过）、`REJECTED`（已驳回）。

| 字段 | 类型 | POST 必填 | PUT 必填 | 说明 |
|---|---|---:|---:|---|
| `financeID` | string | 否 | — | 后端生成；审核走专用 `/audit` 子路由 |
| `projectID` | string | 是 | — | 所属众筹项目 ID，必须存在 |
| `recordType` | string/null | 否 | — | 财务记录类型，如 `MEDICAL`、`FOOD`、`SUPPLIES` |
| `amount` | decimal | 是 | — | 支出金额（元），必须为正数 |
| `invoiceUrl` | string/null | 否 | — | 发票或凭证地址 |
| `auditUserID` | string/null | 否 | — | 审核人 ID；POST 时被后端强制清空，由 `/audit` 接口写入 |
| `auditStatus` | string/null | 否 | — | 审核状态；POST 时被后端强制置为 `PENDING` |
| `publicTime` | datetime/null | 否 | — | 公示时间；POST 时被后端强制清空，由 `/audit` 接口在通过时写入 |

### 3.4 RptStatisticsSnapshot（统计快照）

对应数据库表 `RPT_STATISTICSSNAPSHOTS`。

| 字段 | 类型 | POST 必填 | 说明 |
|---|---|---:|---|
| `snapshotID` | string | 否 | 后端生成；本模块不暴露通用 POST 创建快照接口，仅通过 `/generate/{projectId}` 事务生成 |
| `snapshotDate` | datetime | — | 统计快照对应的日期 |
| `metricCode` | string/null | — | 指标代码，如 `TOTAL_DONATION`（总捐赠）、`TOTAL_EXPENSE`（总支出）、`NET_BALANCE`（净余额）、`DONATION_COUNT`（捐赠笔数） |
| `metricValue` | decimal/null | — | 指标数值 |
| `dimensionType` | string/null | — | 维度类型，如 `PROJECT`（按项目）、`MONTH`（按月）、`CAT`（按猫咪） |
| `dimensionValue` | string/null | — | 维度值，如项目 ID、月份字符串、猫咪 ID |
| `unit` | string/null | — | 单位，如 `CNY`（元）、`COUNT`（次） |
| `generateTime` | datetime | — | 快照生成时间 |
| `remark` | string/null | — | 备注 |

### 3.5 FinancialDisclosureDto（财务公示视图）

由 `FinancialDisclosureController` 组装返回，聚合项目基本信息、已筹金额、已审核通过支出、净余额与明细列表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `project` | `FundCrowdfundingProject`/null | 项目基本信息 |
| `targetAmount` | decimal/null | 目标金额，等同于 `project.targetAmount` |
| `raisedAmount` | decimal/null | 已筹金额，等同于 `project.raisedAmount`（捐赠累计） |
| `totalExpense` | decimal/null | 已审核通过的支出总额 |
| `netBalance` | decimal | 净余额 = `raisedAmount` - `totalExpense`（null 按 0 计算） |
| `donationCount` | integer | 捐赠笔数 |
| `donations` | `FundDonation[]` | 捐赠明细列表；匿名捐赠的 `donorUserID` 由后端通过 `GetForDisclosureByProject` 脱敏 |
| `expenses` | `FundExpenseRecord[]` | 支出明细列表，仅包含 `auditStatus='APPROVED'` 的记录 |

### 4.5 新增众筹项目

| 项目 | 内容 |
|---|---|
| 接口说明 | 新增众筹项目，项目 ID 由后端生成。后端会强制 `raisedAmount=0`，`projectStatus` 未提供时默认 `ACTIVE`，再统一 `ToUpperInvariant` |
| HTTP Method | `POST` |
| URL | `/crowdfunding-projects` |

请求体：见 [FundCrowdfundingProject](#31-fundcrowdfundingproject众筹项目)。

```json
{
  "catID": "cat-orange-0001",
  "title": "小白骨折治疗众筹",
  "targetAmount": 3000.00,
  "startTime": "2026-08-03T00:00:00Z",
  "endTime": "2026-09-03T00:00:00Z",
  "projectStatus": "ACTIVE"
}
```

| 状态码 | 描述 | 响应体 |
|---:|---|---|
| 201 | 创建成功 | 完整 `FundCrowdfundingProject` 对象，其中 `projectID` 为新 UUID，`raisedAmount` 为 0 |
| 400 | 数据为空或 `title` 为空 | 对应的业务错误文本 |
| 400 | 关联猫咪不存在 | 文本：`猫咪 CatID='{catID}' 不存在。` |
| 400 | 目标金额为负 | 文本：`目标金额 TargetAmount 不能为负数。` |
| 400 | 状态不合法 | 文本：`无效的项目状态 '{status}'。允许的状态: ACTIVE, COMPLETED, CANCELLED` |
| 400 | 结束时间早于开始时间 | 文本：`项目结束时间不能早于开始时间。` |

### 4.6 更新项目基本信息

| 项目 | 内容 |
|---|---|
| 接口说明 | 完整更新指定众筹项目的基本信息（不含状态流转） |
| HTTP Method | `PUT` |
| URL | `/crowdfunding-projects/{id}` |

路径参数：`id` 为待更新项目 ID。请求体结构同 `FundCrowdfundingProject`，可省略 `projectID`。

```json
{
  "catID": "cat-orange-0001",
  "title": "小橘绝育与医疗众筹（已更新目标）",
  "targetAmount": 2500.00,
  "raisedAmount": 800.00,
  "startTime": "2026-07-24T00:00:00Z",
  "endTime": "2026-08-30T00:00:00Z",
  "projectStatus": "ACTIVE"
}
```

| 状态码 | 描述 | 响应体 |
|---:|---|---|
| 204 | 更新成功 | 无 |
| 400 | URL 与请求体 ID 不一致 | 文本：`URL 中的 ID 与请求体中的 ID 不匹配。` |
| 400 | `title` 为空或其他业务校验失败 | 对应的业务错误文本 |
| 404 | 项目不存在 | 文本：`未找到 ID 为 {id} 的众筹项目，无法更新。` |

### 4.7 更新项目状态

| 项目 | 内容 |
|---|---|
| 接口说明 | 单独更新项目状态（如发布为 `ACTIVE`、结束为 `COMPLETED`、取消为 `CANCELLED`），状态在后端统一 `ToUpperInvariant` |
| HTTP Method | `PUT` |
| URL | `/crowdfunding-projects/{id}/status` |

路径参数：`id` 为项目 ID。请求体为 `UpdateProjectStatusRequest`：

```json
{
  "newStatus": "COMPLETED"
}
```

| 状态码 | 描述 | 响应体 |
|---:|---|---|

| 400 | `newStatus` 为空或不合法 | 对应的业务错误文本 |
| 404 | 项目不存在 | 文本：`未找到 ID 为 {id} 的众筹项目，无法更新状态。` |

## 9. 交叉测试说明

1. 启动 Oracle，并依次执行 `database/create_tables.sql`、`database/insert_demo_data.sql`、`database/queries/task_shift&crowdfunding.sql`。
2. 启动 API：

   ```powershell
   dotnet run --project src/CampusStrayCatSystem.Core/CampusStrayCatSystem.Core.csproj --launch-profile http
   ```

3. 推荐交叉测试覆盖以下场景：

   - 查询空列表（如查询不存在项目的捐赠，应返回 `200 []`；查询不存在项目的支出明细，应返回 `404`）。
   - 新增众筹项目时：`title` 为空、`targetAmount` 为负、关联猫咪不存在、结束时间早于开始时间，应返回 `400`。
   - 新增众筹项目后，确认 `raisedAmount` 被强制置为 `0`、`projectStatus` 默认为 `ACTIVE`。
   - 记录捐赠时：项目不存在、项目状态非 `ACTIVE`、捐赠人不存在、金额非正、`publicFlag` 非 0/1，应返回 `400`。
   - 记录捐赠时不传 `publicFlag`，确认后端默认置为 `0`（匿名）。
   - 捐赠成功后查询对应项目，确认 `raisedAmount` 已累加。
   - 并发对同一项目（已被取消）发起捐赠，应返回 `409`。
   - 记录支出时在请求体中带 `auditUserID`、`auditStatus='APPROVED'`、`publicTime`，确认后端强制清空为 `PENDING`。
   - 审核支出时：`auditStatus` 传 `PENDING`、`auditUserID` 为空、审核人不存在，应返回 `400`。
   - 对已审核的支出重复调用 `/audit`，应返回 `400`（状态非 PENDING）或 `409`（并发）。
   - 调用 `/financial-disclosure/{projectId}` 时，确认匿名捐赠的 `donorUserID` 被脱敏为 `null`，未审核支出不出现在 `expenses` 中。
   - 调用 `/financial-disclosure/summary` 时，确认仅返回 `ACTIVE` 项目，且 `donations`/`expenses` 为空数组。
   - 调用 `/statistics-reports/generate/{projectId}` 后，再调用 `/statistics-reports/by-dimension/PROJECT/{projectId}`，确认返回 4 条指标记录（`TOTAL_DONATION`、`TOTAL_EXPENSE`、`NET_BALANCE`、`DONATION_COUNT`）。
   - PUT 更新项目时 URL 与请求体 ID 不一致，应返回 `400`。
   - 按状态筛选众筹项目/统计快照时传入非法值，应返回 `400`。

4. 演示数据中可用的外键：

   - 用户：`user-admin-0001`（管理员）、`user-volunteer-01`、`user-volunteer-02`、`user-donor-0001`（捐赠人）
   - 猫咪：`cat-orange-0001`、`cat-white-0002`
   - 众筹项目：`proj-0001`（`ACTIVE`，目标 2000，已筹 800）
   - 捐赠记录：`don-0001`（500，公开）、`don-0002`（200，公开）、`don-0003`（100，匿名）
   - 支出记录：`fin-0001`（300，`APPROVED`）、`fin-0002`（150，`PENDING`）
   - 统计快照：`rpt-0001`—`rpt-0004`（项目 `proj-0001` 的 4 条指标）
